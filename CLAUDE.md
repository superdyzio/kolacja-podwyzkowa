# Rules for AI

This file provides guidance to AI Agent when working with code in this repository.

## Project rules

- Commit subject format: `[<model>] <message>` (e.g. `[Opus 5.5] feat(<change-id>): <phase title> (p<N>)`). Never add a `Co-Authored-By` trailer.
- Source of truth: `context/foundation/` (`prd.md`, `roadmap.md`, `tech-stack.md`, `shape-notes.md`). Changes live in `context/changes/<change-id>/`.
- Unattended (overnight) runs follow `context/foundation/overnight-brief.md` and log decisions, added dependencies and blockers in `context/foundation/overnight-log.md`.
- UI language: Polish. Every user-facing text (pages, errors, API messages) is in Polish.

## Commands

- `npm run dev` — start dev server (Cloudflare workerd runtime)
- `npm run build` — production build (SSR via `@astrojs/cloudflare`); copies `.dev.vars` into `dist/server/`, so rebuild after changing it
- `npm run preview` — preview production build (Astro 7 runs it detached; stop it with `npx astro preview stop`)
- `npm test` — Vitest unit + integration tests (`vitest run`); `npm run test:watch` for watch mode
- `npm run lint` — ESLint with type-checked rules; `npm run lint:fix` to auto-fix
- `npx astro check` — type check (run `npx astro sync` first after changing the env schema)
- `npm run format` — Prettier (includes prettier-plugin-astro + prettier-plugin-tailwindcss)
- `npm run env:local` — write `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` for the local Supabase into `.env` and `.dev.vars`
- `npm run links` — print the organizer and TV links of the event (recovery for a lost organizer link)
- `npm run smoke` — dependency-free HTTP smoke test of the access matrix (`scripts/smoke.mjs`) against a running server, `BASE_URL` env (default `http://localhost:4321`); needs a DB without an event (it creates one)

Pre-commit hooks: husky + lint-staged runs `eslint --fix` on `*.{ts,tsx,astro}` and `prettier --write` on `*.{json,css,md}`.

## Architecture

**Astro 7 SSR app** with React 19 islands, Tailwind 4, Supabase (Postgres only) and shadcn/ui components. Deployed to Cloudflare Workers.

### Rendering mode

Full server-side rendering (`output: "server"` in astro.config.mjs). All pages are server-rendered by default. API routes must export `const prerender = false`.

### Access model (no accounts)

Identity is an unguessable key in the URL path (PRD Access Control, NFR-009): organizer `/o/<key>`, TV `/tv/<key>` (read-only), guest `/g/<key>` (personal link, S-05). Keys: 18 random bytes, base64url, 24 chars.

- `src/lib/access/` — `keys.ts` (`generateAccessKey`, `isWellFormedAccessKey`), `paths.ts` (`parseAccessPath`, `organizerPath`, `tvPath`, `guestPath`), `resolve.ts` (`resolveAccess`, `decideAccess`, `accessFor`, types `Access`, `OrganizerAccess`, `TvAccess`, `GuestAccess`), `messages.ts` (the shared no-access texts). Import from `@/lib/access`.
- `src/middleware.ts` guards every path under `/o/`, `/tv/`, `/g/` and `/api/{o,tv,g}/`. A valid key of the matching role sets `Astro.locals.access` and adds `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Robots-Tag`. Anything else gets the same 404: the `NoAccess` page (`src/components/NoAccess.astro`, also `src/pages/404.astro`) or `{"error":"Brak dostępu"}` for API routes. DB errors throw → `src/pages/500.astro`, never a 404.
- New guarded routes go under those prefixes, e.g. `src/pages/o/[key]/goscie.astro` or `src/pages/api/o/[key]/guests.ts`. Inside, re-check with `accessFor(Astro.locals, "organizer")` (or `context.locals`) and answer 404 when it is null.
- Astro pages: do not `return` from the frontmatter (ESLint `no-misused-promises` crashes on it). Set `Astro.response.status = 404` and render `<NoAccess />` instead.
- `TvAccess` and `GuestAccess` carry no keys; never add organizer-only data (keys, guesses, ranking, drafts) to TV or guest responses, and never another guest's data to a guest response.
- Guest access (S-05): `resolveAccess(db, "guest", key)` = ONE query (guest by `access_key` with `event(id, name, guest_access_enabled)` embedded) → `GuestAccess { role: "guest", event: { id, name }, guest: { id, displayName } }` only while the organizer's switch `event.guest_access_enabled` is on (default OFF). Switch off, revoked, unknown, malformed and other roles' keys all get the identical denial (the smoke compares the bodies); a guest key never opens `/o/…`, `/tv/…`, `/api/o/…`, `/api/tv/…`.
- Guest API routes (`src/pages/api/g/[key]/…`, S-06..S-08 too) start with `const api = guestApi(locals); if (api instanceof Response) return api;` (`src/lib/guest-api.ts`, mirrors `organizerApi`). The current guest is `api.access.guest.id` — never take a guest id from the body, query or params.

### Data access

- The browser never talks to Supabase. All DB access is server-side with the service-role key.
- `src/lib/db.ts` — `getDb()`: the only reader of `astro:env/server` (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`); returns `null` when not configured.
- `src/lib/supabase-client.ts` — `createServiceClient(url, key)` and the `DbClient` type. Business logic takes a `DbClient` parameter and must not import `astro:*`, so Vitest can test it against the local DB.
- `src/lib/event.ts` — the singleton event (`EVENT_ID = 1`, `hasEvent`, `createEvent`). Created once from `/` (POST `/api/event`).
- Guests and groups (S-01), `src/lib/guests/` (`names.ts` pure rules, `service.ts` DB, `summary.ts` counts; import from `@/lib/guests`, but React islands import `names`/`summary` directly):
  - Tables `public.guest` (`id`, `event_id`, `display_name`, `is_absent`, `group_id`, `created_at`) and `public.guest_group` (`id`, `event_id`, `created_at`); both cascade-delete with the event.
  - `display_name`: normalized (`normalizeDisplayName`), 1–40 code points, unique per event case-insensitively (index on `lower(display_name)`); at most `MAX_GUESTS = 100`.
  - Groups: 2–5 members, a guest in at most one group (`guest.group_id`). Create only via the DB function `create_guest_group(p_guest_ids)` (service `createGroup`); dissolve = delete the `guest_group` row (`dissolveGroup`). A trigger dissolves a group that drops below 2 members (e.g. a member deleted). Absent members stay in their group.
  - Service: `getGuestList` (→ `GuestListDto`: guests in Polish alphabetical order, groups with `memberIds`), `addGuests` (all-or-nothing), `updateGuest` (rename / `isAbsent`), `deleteGuest`, `createGroup`, `dissolveGroup`; results are status unions.
  - Organizer API: `/api/o/<key>/guests` (GET, POST `{ text }`), `/guests/<id>` (PATCH `{ displayName?, isAbsent? }`, DELETE), `/groups` (POST `{ guestIds }`), `/groups/<id>` (DELETE); every mutation answers with the whole `GuestListDto`. Page `/o/<key>/goscie` (island `src/components/guests/GuestManager.tsx`).
- Venue plan, rooms and tables (S-02), `src/lib/venue/` (pure `rules.ts`, `image.ts`, `seats.ts`, `pin.ts`, `summary.ts`; DB `service.ts`; `image-response.ts`; import from `@/lib/venue`, but React islands import the pure modules directly):
  - Tables `public.venue_plan` (singleton per event: `mime_type`, `byte_size`, `image_base64`, `updated_at`), `public.venue_room` (`id`, `name`) and `public.venue_table` (`id`, `room_id`, `name`, `seat_count`, `shape`, `pos_x`, `pos_y`); all cascade-delete with the event, tables with their room.
  - Plan image: one screenshot of the whole venue, PNG/JPEG/WebP recognized by magic bytes (`sniffImageType`; the client's header is ignored), ≤ 5 MB (`MAX_PLAN_BYTES` = 5 242 880 B), stored as base64 text (PostgREST would send `bytea` as hex, 2×). Only `getPlanImage` reads the blob; `getVenue` and every list answer carry metadata only (`VenuePlanDto { mimeType, byteSize, version }`, `version` = epoch ms of the upload). Replace = upload again (no delete); pins are kept.
  - Rooms: name only (no geometry), 1–40 chars, unique per event case-insensitively, ≤ `MAX_ROOMS` = 10. Tables: name 1–24 chars unique per event (all tables share one TV plan), 2–20 seats, `shape` `round` | `rectangular`, ≤ `MAX_TABLES` = 40, a room and a pin are required.
  - Pin contract: `x`, `y` ∈ [0, 1] are fractions of the rendered `<img>` box from its top-left corner (4 decimals, `pointToFraction`, `fractionStyle`). Views position pins in a `relative` wrapper sized by the `<img>` itself (`block w-full h-auto` or `max-h`/`w-auto`), with no `object-fit` letterboxing, padding or border on the `<img>`. Image URL: `planImagePath(apiBase, version)` (the middleware forces `no-store`, the version changes the URL).
  - Seats (contract for S-03/S-04, `seats.ts`): a seat is `(table id, 1..seat_count)`. Round: 1..n clockwise, side neighbours i−1/i+1 with wrap-around, no opposite. Rectangular: side A = 1..ceil(n/2), side B = the rest, same direction (position p = seat p on A, seat ceil(n/2)+p on B); side neighbours i−1/i+1 on the same side without wrap-around; opposite = same position on the other side (odd n: the last seat of A has none); no seats at the ends. "Neighbour" = side ∪ opposite (`neighbours()`).
  - Deletion/edit semantics (contract for S-03): structure edits always succeed. Deleting a table (or its room) removes every seat assignment and pinned seat at that table (reference `venue_table` with `on delete cascade`); lowering `seat_count` removes those above the new count (S-03 enforces it and warns first); changing the shape keeps seat numbers (only neighbours change; record S-04 neighbour history as guest pairs at publish time); renaming, moving to another room, moving the pin and replacing the plan never touch seating.
  - Service: `getVenue` (→ `VenueDto`: plan metadata, rooms by id, tables by room then `compareTableNames`), `getPlanImage`, `savePlanImage`, `addRoom`, `renameRoom`, `deleteRoom`, `addTable`, `updateTable`, `deleteTable`; results are status unions.
  - Organizer API: `/api/o/<key>/venue` (GET), `/plan` (PUT, raw image body read with `readBodyBytes` → 400/413/415), `/plan/image` (GET), `/rooms` (POST `{ name }`), `/rooms/<id>` (PATCH `{ name }`, DELETE), `/tables` (POST `{ roomId, name, seatCount, shape, x, y }`), `/tables/<id>` (PATCH any subset, `x`+`y` together; DELETE); every mutation answers with the whole `VenueDto`. TV: `/api/tv/<key>/plan/image` (same image, `nosniff`). Page `/o/<key>/sale` (island `src/components/venue/VenueEditor.tsx`, hook `useVenue`).
- Seating (S-03), `src/lib/seating/` (pure `rules.ts`, `published.ts`, `board.ts`, `tv-layout.ts`; DB `service.ts`; import from `@/lib/seating`, but React islands import the pure modules directly):
  - Working arrangement `public.seat_assignment` (`guest_id` PK, `table_id`, `seat`, `is_pinned`; unique `(table_id, seat)`; cascades with the guest and the table; triggers `check_seat_in_range` and `unseat_beyond_seat_count` keep seats within `seat_count`). This is what the organizer edits; it never reaches the TV directly.
  - Published snapshots `public.seating_snapshot` (`id` identity = the published version, monotonic, never reused; `published_at`), `seating_snapshot_table` (copy of every table: `table_id` `on delete set null`, `room_name`, `name`, `seat_count`, `shape`, `pos_x`, `pos_y`) and `seating_snapshot_seat` (`snapshot_table_id`, `seat`, `guest_id` `on delete set null`, `guest_name` at publish time). Immutable; a snapshot renders without the live venue or guest rows. The TV (and S-05 phones) show the latest snapshot only.
  - DB functions (both take `pg_advisory_xact_lock(3003)`): `seat_guest(p_guest_id, p_table_id, p_seat)` — empty seat → move; taken seat → swap when the guest had a seat, otherwise the occupant becomes unseated; own seat → no-op; raises `GUEST_NOT_FOUND`, `TABLE_NOT_FOUND`, `SEAT_OUT_OF_RANGE`, `GUEST_PINNED`, `SEAT_PINNED`. `publish_seating()` → new snapshot id: copies all tables and the seats of PRESENT guests (absent guests are left out, so marking a seated guest absent is an unpublished change).
  - Pins are locks: a pinned guest cannot be moved, swapped, displaced or unseated until unpinned (`setPinned`); deleting the table or lowering `seat_count` still removes them (S-02 contract). Pins change nothing on the TV. S-04's draw keeps pinned rows as they are.
  - Publish with no change is a no-op (`publishSeating` → `unchanged`, same snapshot id): `isUpToDate` compares fingerprints of the latest snapshot and what `publish_seating()` would write now (`publishableFingerprint` / `snapshotFingerprint`); the board's `upToDate` drives "nieopublikowane zmiany".
  - Service: `getAssignments`, `seatGuest`, `unseatGuest`, `setPinned`, `getLatestSnapshot`, `getSnapshot(id)` (→ `SeatingSnapshot` with `tables`/`seats`, ids nullable), `getSeatingBoard` (→ `SeatingBoardDto { guestList, venue, assignments, published, previous, upToDate }`; `previous` = the snapshot before the latest, S-04), `publishSeating`, `getSeatingVersion`, `getTvSeating` (→ `TvSeatingDto`), `getSeatOccupancy`; results are status unions.
  - S-04 restore of an older snapshot: map rows back by `table_id`/`guest_id`, skip rows whose id is now null, skip seats above the table's current `seat_count`, keep current pinned rows (a pinned guest who is absent stays as is — S-04 decides). Neighbour history = guest pairs from snapshot seats (`neighbours()` in `seats.ts`); the group "next to each other" rule is `areConsecutiveSeats`.
  - Organizer API: `/api/o/<key>/seating` (GET board), `/seating/guests/<id>` (PUT `{ tableId, seat }` → 404/400/409; PATCH `{ pinned }` → 409 when not seated; DELETE → 409 when pinned), `/seating/publish` (POST → 201 published / 200 unchanged); every answer carries the whole board. Page `/o/<key>/rozsadzenie` (island `src/components/seating/SeatingEditor.tsx`, hook `useSeatingBoard`): select a guest, then a seat; warnings (`seatingWarnings`: split groups, absent guests with a seat, missing seats) never block. `/o/<key>/sale` confirms table/room deletes and lower seat counts naming who loses a seat (`occupantsRemovedBy`, `describeRemovedOccupants`, `occupancyAfter`).
  - TV polling contract (also for S-05): `GET /api/tv/<key>/seating?since=<version>` → 204 with no body when `since` equals the current version (two tiny queries), else 200 `TvSeatingDto { version, planVersion, publishedAt, tables: [{ name, shape, seatCount, x, y, seats: [{ seat, name }] }] }` — no ids, pins, absences or keys. `version` is an opaque token `"<snapshot id>.<plan version>"` (0 for none; `seatingVersion`); clients send it back and compare for equality only. The TV (`/tv/<key>`, island `src/components/tv/TvSeatingView.tsx`, hook `useTvSeating`) polls every 2.5 s with a `setTimeout` chain and a 4 s abort, keeps the last state on errors and shows „Brak połączenia — ponawiam…” after 3 failures.
  - TV layout: the plan `<img>` is sized by `containBox` from its natural size (contain, upscaling, centred; no plan → blank 16:9 stage), pins become dots, and one card per table (`TableCard`, names 3vh, `tableCardColumns`: rectangular = two sides, round split above 8 names) is placed by `layoutCards` (start on the pin, clamp to the screen, fixed passes pushing overlapping pairs apart; deterministic). Positions are written to the DOM in a layout effect.
- Draw and restore (S-04), `src/lib/seating/` (pure `neighbours.ts`, `draft.ts`, `draw.ts`; DB in `service.ts`):
  - The draw runs in the organizer's BROWSER (`drawSeating(input, historyPairs, { random, timeBudgetMs?, maxIterations?, now? })` in `useSeatingBoard.draw()`; Cloudflare has ~10 ms CPU per request). Inputs: a fresh board (`GET /seating`) and the neighbour history (`GET /seating/history`). Hard rules: every PRESENT non-pinned guest gets exactly one free existing seat; pinned rows never move (a pinned ABSENT guest keeps the seat, which shows empty on the TV); non-pinned absent guests get no seat; each group's present members (≥ 2) sit at one table on seats forming one block of side neighbours (`areConsecutiveSeats`: round = an arc with wrap-around, rectangular = a run on ONE side, opposite never joins); pinned group members fix the table and the rest must join their block. Soft rule: minimise repeated neighbour pairs (`neighbours()` = side ∪ opposite between two occupied seats; pairs from the same current group are excluded). Infeasible (`too-many-guests`, `group-too-large`, `pinned-group-split`, `pinned-group-no-room`, `groups-do-not-fit`) → `DRAW_INFEASIBLE_MESSAGE` + `describeDrawProblem` lines, nothing is sent.
  - Solver: mulberry32 (`createRandom(seed)`, `randomSeed()`), static feasibility checks, randomised backtracking placement of groups (forward checking), singles shuffled, then local search with annealing (single swap/move, group relocate/permute) on an incremental cost; stops at 0 repeats, `maxIterations` or the budget (`DEFAULT_DRAW_BUDGET_MS` = 1200, clock read every 256 iterations). Each draw has a new seed, so a redraw differs. Tests pass a seed and `maxIterations`, never a clock.
  - History = union of guest pairs over ALL published snapshots (`getNeighbourHistory` → `NeighbourHistoryDto { snapshotCount, pairs }`), computed with each snapshot's own shape and seat count; deleted guests skipped; snapshot tables/seats read in pages of 1000 (PostgREST `max_rows`). `repeatedNeighbours(board, pairs)` drives the stats (present seated guests only).
  - Saving a draft: `POST /api/o/<key>/seating/draft { seats: [{ guestId, tableId, seat }] }` (≤ 200 rows) → `saveDraft`: `validateDraft` re-checks the hard rules against the current data (409 `DRAFT_STALE_MESSAGE` + `problems`), then DB function `replace_seating(p_seats jsonb)` (lock 3003, venue tables locked `for share`) deletes every NON-pinned `seat_assignment` row and inserts the draft in one transaction (constraint failure → 409, nothing changed). 200 with the board. The draft is only the working arrangement: TV and phones (S-05) keep the latest snapshot until `POST /seating/publish`, which is unchanged.
  - Restore: `POST /seating/restore { snapshotId }` → `restoreSnapshot` (`restoreSeats`: skips deleted guests/tables, seats above today's `seat_count`, seats of current pinned rows, guests now absent; keeps pinned rows) → 200 `{ ...board, notice }` (`describeRestore` names who has no seat) / 404 `SNAPSHOT_NOT_FOUND_MESSAGE` / 409. „Odrzuć zmiany” restores the latest snapshot, „Wróć do poprzedniego rozkładu” the `previous` one; the organizer publishes it afterwards. `GET /seating/history` → `NeighbourHistoryDto`. All three are organizer-only (TV key → 404).
  - UI: `DrawPanel` under the publish bar („Wylosuj projekt” / „Losuj ponownie”, repeat stats, history count, discard, back to previous). Draw/restore ask `window.confirm` only when they would replace unpublished changes that are not an untouched draw (`origin !== "draw"`). After a publish (201) the hook refetches the history.
- Guest links and the guest's seat view (S-05), `src/lib/guest-links/` (pure `state.ts`, `links.ts`, `summary.ts`; browser-only `qr.ts`; DB `service.ts`; import from `@/lib/guest-links`, but React islands import the pure modules directly and only client code imports `qr.ts`):
  - Columns `guest.access_key` (unique, 24-char base64url; the DB default `translate(encode(extensions.gen_random_bytes(18), 'base64'), '+/', '-_')` gives every row a key, whatever inserts it) and `event.guest_access_enabled` (default `false`). Revoke = `revokeGuestKey` writes a fresh `generateAccessKey()`; the old link is dead at once. `GuestListDto` never carries keys; only `GuestLinksDto` (organizer) does.
  - Service: `getGuestLinks` (→ `GuestLinksDto { enabled, guests: [{ id, displayName, key }] }`, Polish order), `getGuestAccessEnabled`, `setGuestAccess`, `revokeGuestKey`, `getGuestState(db, guest)` (→ `GuestStateDto { version, name, status: "unpublished" | "unseated" | "seated", seat: { table, room, seat, shape, seatCount, x, y } | null, planVersion }` — the seat from the LATEST snapshot via one `seating_snapshot_seat` row filtered by `guest_id`, the name live from the guest row; absent guests are "unseated"), `getGuestStateVersion`. `getPublishedVersion` (seating service) gives the snapshot id, plan version and seating token in two tiny queries.
  - Organizer API: `/api/o/<key>/guest-links` (GET, PATCH `{ enabled }`), `/guest-links/<id>/revoke` (POST → 404 unknown); every answer is the whole `GuestLinksDto`. Pages `/o/<key>/linki` (island `src/components/guest-links/GuestLinksManager.tsx`, hook `useGuestLinks`: switch with confirm on OFF, copy with a select-the-field fallback on non-secure origins, revoke with confirm, localhost warning via `isLocalOrigin`) and `/o/<key>/karteczki[?guest=<id>]` (A4, 2 × 4 cards of 95 × 69 mm with cut lines; `@page { margin: 0 }` so browsers print no header with the organizer URL). Links are built from the request origin (`guestUrl(Astro.url.origin, key)`).
  - QR codes are generated ONLY in the browser: the card sheet renders `[data-qr="<url>"]` placeholders and its client script (`src/components/guest-links/qr-cards.ts`) fills them from `qrMatrix`/`qrSvgPath`/`qrViewBox` (`qrcode`, error correction M, 4-module quiet zone). Never import `qr.ts` from server code (Worker CPU budget; `dist/server` must not contain `qrcode`). `qr.test.ts` decodes the drawn path with `jsqr` and checks the orientation against `BitMatrix.get(row, col)`.
  - Guest API: `GET /api/g/<key>/state?since=<version>` → 204 when unchanged (middleware lookup + three tiny queries), else 200 `GuestStateDto`; `version` = `guestStateVersion(<seating token>, name, guess)` (opaque, ≤ 64 chars). `GET /api/g/<key>/plan/image` (same image as the TV). A later slice needing live guest state adds a field to `GuestStateDto` and a part to the token instead of starting a second poll (S-06 did: `guess`).
  - Guest page `/g/<key>` (`src/pages/g/[key].astro`): `<main>` (max-w-md, mobile-first) with a header (event name) and stacked `<section>`s. The first is the seat island `src/components/guest/GuestSeatView.tsx`, then the guess island `GuestGuessView.tsx` (S-06). Every guest island reads the live state with `useGuestState(apiBase, initial)` → `{ state, offline, changed, push, refresh }`, backed by ONE shared poll per phone (`src/components/hooks/guest-state-store.ts`: module-level store per `apiBase`, browser only, ref-counted by subscribers, read via `useSyncExternalStore`; polls every 2.5 s with a 4 s abort, pauses while the page is hidden and polls at once when it is visible again; 404 → state null (no-access texts), keeps polling; network errors keep the last state, `offline` after 3; `push(state)` takes a fresher state from another request and makes older in-flight polls be ignored; `changed` („Nowe miejsce!”) reacts to seat changes only). S-07 (question draw) and S-08 (AI topic) add their own `<section>` below with an island from `src/components/guest/` receiving `apiBase` (`/api/g/<key>`) and `initial`, and reuse the store — never a second poll.
- Guesses and the ranking (S-06), `src/lib/guesses/` (pure `amount.ts`, `ranking.ts`, `board.ts`; DB `service.ts`; import from `@/lib/guesses`, but React islands import the pure modules directly):
  - Table `public.guess` (`guest_id` PK → `guest` `on delete cascade`, `event_id`, `amount_grosze` integer 0…1 000 000 000, `entered_by` `'guest' | 'organizer'`, `updated_at`) — at most one guess per guest. Columns `event.guess_intake_open` (default `true`) and `event.correct_amount_grosze` (nullable, same bounds).
  - Money is integer grosze end to end (1 zł = 100), never floats. `parseAmount(text)` → `{ ok, grosze } | { ok: false, message }` accepts „1500”, „1 500”, „1499,99”, „1499.99”, „1 499,99 zł”, „PLN”, NBSP, „1500,-”; refuses „1.500”, > 2 decimals, negatives and > 10 000 000 zł with Polish messages. `formatAmount` → „1 499,99 zł” (U+00A0 grouping and before „zł”, always 2 decimals; hand-rolled, not `Intl`, so SSR and browsers match), `formatAmountInput` → „1500” / „1499,99” (prefill that parses back), `describeDifference` → „dokładnie!” / „o X za mało” / „o X za dużo”.
  - Intake rule: a guest write goes through DB function `save_guest_guess(p_guest_id, p_amount_grosze)`, which locks the event row `for share` only while intake is open (else `INTAKE_CLOSED`) and upserts with `entered_by = 'guest'`; a save never lands after a committed close. Organizer writes (`saveGuessByOrganizer`, `deleteGuess`) skip the check (proxy entries also after closing). The correct amount is independent of intake.
  - Service: `getGuessBoard` (→ `GuessBoardDto`), `setGuessIntakeOpen`, `setCorrectAmount(db, grosze | null)`, `saveGuessByOrganizer`, `deleteGuess`, `submitGuestGuess` (→ `saved | closed | not-found`), `getGuestGuess(db, guestId)` (→ `GuestGuessDto { intakeOpen, amountGrosze }`, one query; feeds `GuestStateDto.guess` and the guest token).
  - Ranking (contract for S-09 caching): pure `rankGuesses(guesses, correctAmountGrosze)` in `src/lib/guesses/ranking.ts` — absolute distance in grosze, competition places (1, 2, 2, 4), `tied` flag, inside a place by Polish name then id. `GuessBoardDto { intakeOpen, correctAmountGrosze, guests: [{ id, displayName, isAbsent, amountGrosze | null, enteredBy | null }], missing: [{ id, displayName, isAbsent }], ranking: GuessRankingDto | null }`; `GuessRankingDto { correctAmountGrosze, entries: [{ place, tied, guestId, displayName, isAbsent, amountGrosze, differenceGrosze, distanceGrosze }] }` is self-contained (renders without anything else), best first; `placesFromLast(ranking)` → readout steps (last place first, tied guests together). Absent guests' guesses are ranked; guests without a guess are only in `missing`.
  - APIs: organizer `GET|PATCH /api/o/<key>/guesses` (`PATCH { intakeOpen?, correctAmount?: string | null }`), `PUT|DELETE /api/o/<key>/guesses/<guestId>` (`{ amount }` as typed; 404 unknown guest) — every answer is the whole `GuessBoardDto`; guest `PUT /api/g/<key>/guess { amount }` (strict body, the guest is the key's owner) → 200 `GuestStateDto`, 400 parse message, 409 „Przyjmowanie strzałów jest zamknięte.”.
  - Guardrail: guests get only `GuestStateDto.guess` (own guess + intake flag); others' guesses, the correct amount and the ranking never reach guest or TV routes (`TvSeatingDto` unchanged). The smoke checks it on the APIs and the rendered pages.
  - Page `/o/<key>/strzaly` (island `src/components/guesses/GuessManager.tsx`, hook `useGuessBoard`: answers replace the board, re-read every 5 s while visible and idle, reads started before a save are ignored): intake card → correct amount → „Czytaj od końca” + `RankingTable` → „Brakuje strzałów” → every guest with „Wpisz”/„Popraw”/„Usuń strzał” (`AmountForm`, client-side `parseAmount`). `RankingReadout.tsx` is a full-screen dialog over a frozen copy of the ranking (one place per step, „Dalej”/„Wstecz”/„Zamknij”, → Space Enter ← Esc). Shell card summary `formatGuessSummary` („Przyjmowanie otwarte · strzały: 32 z 40 · ranking gotowy”).
- API routes: `organizerApi(locals)` (`src/lib/organizer-api.ts`) does the organizer re-check and returns the DB client; `src/lib/http.ts` has `jsonResponse`, `jsonError`, `readJsonBody` (zod, 400 "Nieprawidłowe dane."), `readBodyBytes` (raw upload with a byte cap), `parseId`. Islands share API failure parsing via `src/components/hooks/api-failure.ts`. Validate with `import { z } from "astro/zod"` (zod ships with Astro; no separate dependency).
- New DB functions: `set search_path = ''` and `revoke execute … from public, anon, authenticated` (Supabase grants EXECUTE to them by default).
- Supabase errors always throw; `null`/empty results mean "not found".
- `src/db/database.types.ts` — hand-written `Database` type (generated-types shape); extend it with every migration.

### Key conventions

- **Path alias**: `@/*` maps to `./src/*` (tsconfig paths; mirrored in `vitest.config.ts`).
- **Astro components** for static content/layout; **React components** only when interactivity is needed.
- **Tailwind class merging**: use the `cn()` helper from `@/lib/utils` (clsx + tailwind-merge) for conditional/merged class names. Do not concatenate class strings manually.
- **shadcn/ui**: components live in `src/components/ui/`, "new-york" style variant. Install new ones with `npx shadcn@latest add [name]`.
- **API routes**: use uppercase `GET`, `POST` exports; validate input with zod.
- **Supabase migrations**: `supabase/migrations/` using naming format `YYYYMMDDHHmmss_short_description.sql`. Every new table: `enable row level security`, no policies for `anon`/`authenticated`, and `revoke all on table ... from anon, authenticated` (Supabase grants them by default).
- **React**: no Next.js directives ("use client" etc.). Extract hooks to `src/components/hooks/`.
- **Services/helpers** go in `src/lib/` (or `src/lib/services/` for extracted business logic).
- **Shared types** (entities, DTOs) go in `src/types.ts`.

### Tests

- Unit tests next to the code: `src/**/*.test.ts`.
- DB integration tests: `tests/integration/*.test.ts`, wrapped in `describe.skipIf(!hasLocalDb)` from `tests/integration/helpers.ts`. They run only when `SUPABASE_URL` points at `127.0.0.1`/`localhost`. Files run sequentially (`fileParallelism: false`).
- Integration tests reuse the existing event and may delete only rows they created themselves.
- HTTP-level behaviour (status codes, headers, page bodies) is checked by `npm run smoke` against the production preview.

### Environment

- Node.js v22.14.0 (see `.nvmrc`)
- Env vars: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (server-only secrets in the `astro.config.mjs` env schema). Locally: `npm run env:local` writes both `.env` and `.dev.vars` (gitignored).
- Local Supabase (Docker), database + REST + gateway only: `npx supabase start -x gotrue,realtime,storage-api,imgproxy,studio,postgres-meta,mailpit,edge-runtime,logflare,vector,supavisor`, then `npx supabase migration up`. `supabase status` prints no API keys in this mode, which is why `env:local` exists.
- Deploy: `npx wrangler deploy` (requires Cloudflare account + `wrangler` auth); secrets via `npx wrangler secret put`.

## CI

GitHub Actions workflow (`.github/workflows/ci.yml`) on every push and PR to `main`:

- `ci` — lint, `astro check`, `npm test` (DB integration tests skip) and build. Optional repository secrets `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.
- `smoke` — local Supabase (CLI from devDependencies), `npm run env:local`, `npm test` with DB tests, build, production preview and `npm run smoke`.
