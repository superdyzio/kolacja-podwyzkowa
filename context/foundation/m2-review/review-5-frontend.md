## Findings

### 1. `[medium]` Read-only previews use `inert`, which removes the whole preview from the accessibility tree
- Location: `src/components/lead/ReadOnlyFrame.astro:17-24` (`inert={readOnly}` + `aria-label` on the same element). Used by `src/pages/panel/wydarzenia/[id]/[sekcja].astro:69,138-254` (`readOnly = mode !== "staff-leads"`, i.e. the staff preview while the client leads AND the admin's support mode), `src/pages/panel/szablony/[id].astro:56-62` (support mode), `src/pages/panel/wydarzenia/[id].astro:302-309` (event branding while the client leads), `src/pages/o/[key].astro:355,376,390`, `src/pages/o/[key]/potwierdzenia.astro:52`, `src/pages/o/[key]/quiz.astro:55` and the other client section pages while „Lokal prowadzi” is on.
- Failure scenario: a screen-reader user who is a manager opens `/panel/wydarzenia/<id>/goscie` (or `zamowienia`, `potwierdzenia`, `quiz`) while the client leads to read the guest list / order board / RSVP answers; the platform admin reads a restaurant's event in support mode; the client opens their own `/o/<key>/potwierdzenia` while the venue leads. In every case the content is inside an `inert` subtree, which browsers exclude from the accessibility tree (and from find-in-page / text selection) — the page is announced as empty below the banner. The frame's own `aria-label` (`leadMessages().readOnlyLabel`) is placed on the inert element and so is never exposed either. The task's intent was "no control reachable", but `inert` also blocks reading, which is the whole purpose of a preview and of support mode.
- Secondary effect: `ModuleOff` (with its only link „Wróć do wydarzenia”) is rendered INSIDE the frame at `[sekcja].astro:201,215-217,240`, so in read-only mode that link cannot be clicked or focused.
- Evidence: `ReadOnlyFrame.astro:19` `inert={readOnly}`; `ReadOnlyFrame.astro:20` `aria-label={readOnly ? leadMessages(locale).readOnlyLabel : undefined}`; `[sekcja].astro:69` `const readOnly = mode !== "staff-leads";`.
- Fix sketch: keep the content readable — replace `inert` with `pointer-events-none select-text` plus a `readOnly`/`disabled` prop on the islands (disable buttons/inputs, `aria-disabled` on the drawing), or at least move the `aria-label` to a visible heading; render `ModuleOff` outside the frame.
- Confidence: high.

### 2. `[low]` The floor stays fully interactive after the app's own denial (only a note is shown)
- Location: `src/components/orders/OrderManager.tsx:191-213` (floor mode with `readout`), compare `src/components/restaurant/RestaurantView.tsx:45-53`.
- Failure scenario: a waiter has `/panel/obsluga/<id>` or `/kelner/sala/<id>` open past noon the next day, after the event is archived, after „Wyloguj wszędzie” on another device, or after the per-event waiter was revoked. `useOrderBoard`'s poll gets the guard's 401/404 → `denied = true`; the page shows the amber note `so.liveGone` but every „Wydane” box, piece chip, refill form and drink form stays enabled; each tap answers 401/404 and surfaces as a generic failure. The tablet (`RestaurantView`) replaces the whole view with the `gone` alert in the same situation.
- Evidence: `OrderManager.tsx:191` `{readout && (offline || denied) && (<p role="status" …>{denied ? so.liveGone : …}` — nothing else keys off `denied`.
- Fix sketch: when `readout && denied`, render the same `gone` alert as `RestaurantView` (or pass `disabled` down / short-circuit `send`).
- Confidence: high.

### 3. `[low]` Brand-name inputs accept 120 characters while the server's rule is 80
- Location: `src/components/branding/EventBrandingManager.tsx:46` (`maxLength={120}`; the server rule is `BRAND_NAME_MAX = 80` at `src/lib/branding/rules.ts:12`, enforced by `parseBrandName` at `:77` — the zod body only caps at 400, so the 80 check is the one that answers 400), `src/components/branding/RestaurantBrandingManager.tsx:51` (`maxLength={120}`; `RESTAURANT_NAME_MAX = 80` at `src/lib/platform/rules.ts:7`, `parseRestaurantName` at `:22`).
- Failure scenario: the client types an 81–120-character company name, presses „Zapisz” → a round-trip 400 with the rule's message; no client-side hint, unlike every other form that mirrors the server's constant (`EVENT_NAME_MAX`, `WAITER_NAME_MAX_LENGTH`, `OWNER_NAME_MAX`).
- Fix sketch: use `BRAND_NAME_MAX` / `RESTAURANT_NAME_MAX` for `maxLength` (and show the rule text before sending).
- Confidence: high.
- Note on severity of finding 1: `context/foundation/prd-v2.md` has no explicit accessibility NFR (grep for WCAG / dostępność / czytnik / klawiatura finds nothing), so it is reported as a usability defect, not a spec violation.

### 4. `[low]` The TV's live region announces only the first update
- Location: `src/components/tv/TvSeatingView.tsx:179-182`.
- Failure scenario: `<p className="sr-only" aria-live="polite">{updates > 0 ? t.updated : ""}</p>` — the text is identical from the second 200 answer on, so assistive technology is told about the first publish only; later publishes and spotlight changes are silent. (`updates` is counted but never rendered.)
- Fix sketch: render a changing sentence (`t.updated` + the count, or alternate two phrasings) or use `aria-atomic` with the publish time.
- Confidence: medium (the TV is rarely used with AT; the TvQuiz and spotlight layers have their own regions).

## Checked and fine
- Polling hooks (`useRsvpBoard`, `useQuizBoard`, `useOrderBoard`, `useRestaurantView`, `useTvSeating`, `useOfflineSync`, `StaffReadoutPage`, `guest-state-store`): one request at a time (setTimeout chains), `AbortController` + timeout, timers and listeners removed on unmount, visibility pause and immediate poll on return, `generation`/`waiting` guards so a read started before a save never overwrites a fresher board, `push()` bumps the generation, `stop()` nulls `active` before aborting so an unmount never counts as a failure. `useRoomRotation` keeps its clock across identical polls.
- One-action hooks (`useEventCard`, `useTeam`, `useEventWaiters`, `usePlatformRestaurants`, `useEventModules`, `useBrandingApi`, `usePriceList`, `useGuestImport`, `useEventReset`): `pending` disables every control; stale answers dropped by request id (`useGuestImport`, `usePriceList`); 404 → re-read or „gone” state with a way back.
- Guest double taps: `GuestRsvpView` and `GuestQuizView` disable their buttons/fieldset while `saving`; `OrderLineRow` tracks in-flight ticks per line; `useOrderBoard.send` is a serial queue.
- i18n: no hard-coded single-language UI text in components or pages (scan for Polish diacritics, literal `aria-label`/`title`/`placeholder`/`alt`, `window.confirm(` literals, JSX text literals); all confirms, aria labels and error texts come from `defineMessages` dictionaries; `LanguageSwitch` carries both labels; among string-literal entries the only identical PL/EN values are proper nouns/symbols („Pub quiz”, „E-mail”, „Logo”, „halal”, „Ranking”, „Format”, „Panel”); function-valued entries were not compared mechanically.
- Astro pages: no `return` in any frontmatter; every new page does one guard call → `Astro.response.status = 404` + `<NoAccess />`; `[sekcja].astro` and `szablony/[id].astro` render support mode without `client:*` (no polling log rows); `linki` is 404 in support mode; `PriceListEditor` stays outside the read-only frame for members only.
- White-label: every `/g`, `/tv`, `/r`, `/o`, `/kelner` page passes its own `<Layout title>`; `NoAccess` and `500` pass theirs; `PRODUCT_NAME` appears only on staff pages (home, login, `/haslo`, `/panel`, legal pages); `BrandHeader`, cards and prints never name the product; the legal links on `/kelner` are explained by the page's own comment (S-30, "a staff door") — not found in `overnight-log.md ## Decyzje`, so it is a code-level decision, not a logged one.
- Hydration: `TvSpotlight` draws `Math.random` only when `spin` (never for the spotlight present at load); `useTvScreenSize` returns the 1080p default on the server and during hydration; every `new Date()` in render sits behind a value that is `undefined` during SSR (`useOfflineCache`, `useStaffReadoutEntry`); `StaffLinkCard.toLocaleString` is reached only after an action (five callers checked); `formatEventDate`/`formatDateTime`/`formatSupportTime`/`formatSavedAt` are hand-rolled from Intl parts with a fixed zone, so SSR and browser agree; `RsvpManager`'s `datetime-local` default is derived from the event date.
- Controlled inputs: `TeamMemberRow`'s role `<select>` is controlled by the server value, so cancelling the confirm restores the stored role; `RsvpManager` keeps drafts across re-reads (the `shownFor` pattern) and a 400 re-read does not wipe them; `QuizQuestionForm`/`OrderItemForm` edit drafts survive polls.
- Dialogs/focus: `ResetPanel` uses a native `<dialog>` with `showModal`, blocks Esc while pending (`onCancel`), moves focus to the result button and back to the opener, locks body scroll; `MapSearch` Escape clears and refocuses with `stopPropagation` so a picked dish survives; `aria-pressed` on toggles, `role="status"`/`"alert"` on messages, `aria-live` on counters.
- `GuestModuleGate`'s `hidden` + `display: contents` works because Tailwind 4's preflight sets `[hidden] { display: none !important }`.
- Staff offline readout: `scope` props are stable objects, so `useStaffReadout` saves only on real changes; denial clears the copy and the worker; `/logowanie` and `/kelner` (without a session) ship `clearStaffReadoutsOnPage()`; the waiter floor has no `/panel` link and confirms logout.
- Print CSS: `@page` A4/A3 `margin: 0`, mm units, `break-after: page`, `break-inside: avoid`, `print-color-adjust: exact`, `print:hidden` toolbar, `languageSwitch={false}`; the client's print uses relative links and `./logo` (no key in HTML); the 1 mm/296 mm trick avoids blank pages.
